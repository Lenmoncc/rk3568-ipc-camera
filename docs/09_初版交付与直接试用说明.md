## 4. 当前模块、线程与资源归属

| 模块 | 运行归属 | 主要资源及释放时机 |
| --- | --- | --- |
| V4L2 / ALSA 采集 | 视频、音频采集线程 | 设备句柄、MMAP 或 PCM 缓冲；停止采集后释放 |
| MPP / AAC 编码 | 视频、音频编码线程 | 编码器和输入缓冲；原始队列排空后完成 EOS/flush |
| H.264 桥接与分发 | 编码线程内同步调用 | 组装视频分片；为每个输出建立独立 AVPacket 引用 |
| MP4 封装 | 本地输出线程 | 独立音视频包队列、文件及封装上下文；写 trailer 后关闭 |
| FLV 封装 | RTMP 输出线程 | 独立音视频包队列、FLV 上下文；失败时禁用网络分支 |
| 网络 AVIO | 同程序 exec 的专属子进程 | RTMP 连接；监督超时后只终止并回收该子进程 |
| 生命周期管理 | 主线程 | 配置、共同时间起点、停止状态与 join；全部使用者退出后销毁队列 |

最多六个业务线程，另加一个网络传输子进程。每路媒体只编码一次；两个输出持有不同 AVPacket 元数据，底层只读数据可共享引用。
队列容量固定；视频/音频分别排队；停止时按采集、编码、输出的依赖顺序排空。
详细接口、所有权、时间戳及失败语义见第 02、07、08 号说明和源码函数注释。

## 6. 可执行文件的维护规则

- `bin/` 根目录的正式 ARM64 程序不再忽略，随源码交付。
- `build/`、`bin/` 内主机测试子目录、日志、录制媒体继续忽略。
- `make clean` 只清理 `build/`，保留正式二进制，避免下载工程后误清理掉试用入口。
- 修改业务源码后，用原 SDK 构建 `sh scripts/build.sh -B all queue-test`，检查架构并更新 `bin/SHA256SUMS`。
