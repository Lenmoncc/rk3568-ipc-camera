# IPC 模块骨架说明

本次补齐模块文件、公共类型、接口声明及最小构建入口。各业务源码含职责与实现任务注释，尚未定义头文件中的业务函数；不提供“返回成功”的假实现。main 仅显示骨架状态后退出。

## 文件布局

- `include/`：11 个模块头文件，以及 `app.h`、`media_types.h`。
- `src/`：11 个模块源码和 `main.c`。
- `configs/ipc.conf`：配置草案，尚未被读取。
- `scripts/`：主工程构建和启动脚本。
- `shell/`：保留已有环境检查脚本，与业务启动脚本分开。
- `demo/`：原样保留已验证实验。

## 在 Ubuntu 编译骨架

在项目根目录执行：

```bash
sh scripts/build.sh
```

SDK 不在默认位置时：

```bash
SDK_ROOT=/实际路径/rk3568_linux_sdk sh scripts/build.sh
```

生成 `bin/ipc_camera`。本阶段不链接 FFmpeg、ALSA、MPP，不能用骨架编译通过来证明这些开发依赖已齐全。业务接入时从 SDK 配套 sysroot 增加检查和链接参数；不升级 FFmpeg。

将 `bin/` 和 `scripts/` 按相对位置传到板端，在项目目录执行：

```bash
sh scripts/run.sh
```

输出包含 `scaffold` 和 `NOT IMPLEMENTED`。当前不读配置、不打开设备、不创建线程、不推流、不录像。main 没有调用未实现的模块接口，因此可以编译链接；以后接入接口前必须完成对应定义。


## 数据与接口约定

- `IpcRawFrame` 保存应用拥有的 NV12/PCM 数据，不能保留已经交还驱动的地址。
- `IpcEncodedPacket` 对应一路输出独立持有的 AVPacket 对象，可共享底层引用数据。
- 队列 `try_push` 成功才转移所有权；失败仍由调用方释放或处理。
- `pop` 返回 1 为成功，0 为已关闭且已空，负值为错误；其他 int 型初始化/处理接口约定 0 成功、负值错误。
- 队列关闭后应排空已有数据；销毁必须在所有使用线程退出后进行。
- 编码器持有流参数，输出模块复制参数；封装头须等待必要编码信息就绪。
- 编码器线程的 `arg` 为应用上下文，内部成员和完整线程协调将在后续实现。
- 音视频双队列的联合等待、输出退出后的分发控制及错误码将在实现阶段细化。
