# 配置与日志模块实现说明

本阶段把已在 RK3568 上启动成功的工程骨架，推进为能够读取配置、检查错误并输出统一日志的基础程序。实现范围为配置、日志、命令行和启动脚本；采集、队列、编码、推流和录像仍未接入。

## 一、背景与任务

原程序只输出固定的骨架说明，无法知道实际设备、分辨率、音频参数和输出地址。后续接入硬件前，需要先让配置错误能够被定位，并建立统一日志接口。

本阶段任务：

1. 读取 `configs/ipc.conf`，把文本参数转换为 `IpcConfig`。
2. 检查缺失键、重复键、未知键、数值范围和字符串长度。
3. 输出带时间、级别和模块名的日志。
4. 在主程序中完成参数解析、配置加载、校验、摘要输出和退出。
5. 从任意工作目录启动时，启动脚本仍能找到配套配置。

编译继续使用 SDK 原有交叉工具链；FFmpeg 保持 4.4.1。本阶段没有调用 FFmpeg、ALSA 或 MPP，因此暂不新增这些库的链接依赖，只使用 libc 和 pthread。

## 二、当前配置如何填写

### 2.1 固定方案与开发初值

| 参数 | 当前值 | 含义 |
| --- | --- | --- |
| 视频设备 | `/dev/video0` | 已确认的视频入口 |
| 视频尺寸与格式 | 1280×720、NV12 | 初版固定方案 |
| 视频编码 | H.264 | 后续由 MPP 实现 |
| 目标帧率 | 30fps | 目标参数，不是实际采集测量值 |
| 视频码率与 GOP | 2000000bit/s、30 帧 | 初始建议，可在范围内调整 |
| 音频设备 | `hw:0,0` | 已枚举的板载录音设备 |
| 音频采样率与声道数 | 48000Hz、1 声道 | 开发初值，现有记录未明确验证结果；接入音频前换成已验证值 |
| 音频格式与编码 | S16_LE、AAC | 后续需要转换为 AAC 接受的 FLTP |
| 音频码率 | 128000bit/s | 初始建议 |
| 录像路径 | `/userdata/record/ipc.mp4` | 仅校验路径格式，本阶段不创建文件 |

配置值必须能够通过静态校验，但通过校验不等于硬件支持。摄像头、声卡的参数协商仍属于后续采集模块职责。

### 2.2 SRS 地址暂时占位

当前配置为：

```ini
output.rtmp_enabled=false
output.rtmp_url=rtmp://SRS_SERVER_IP/live/stream
```

规则如下：

| 是否启用 RTMP | URL | 校验结果 |
| --- | --- | --- |
| `false` | 空字符串 | 允许 |
| `false` | `rtmp://SRS_SERVER_IP/live/stream` | 允许，输出禁用提示 |
| `false` | 格式正确的真实地址 | 允许，但仍不启用 |
| `true` | 空字符串或 `SRS_SERVER_IP` 占位主机 | 拒绝，并报告 URL 所在行 |
| `true` | 格式正确的真实地址 | 静态校验通过；当前阶段仍不会连接服务器 |

以后接入实际推流时，应同时把开关改为 `true` 并替换主机地址。`rtmp_enabled` 已进入配置对象；真正启动媒体线程时，还需要根据此字段决定是否创建网络输出。

本阶段 URL 支持 `rtmp://hostname或IPv4[:port]/app/stream`。端口范围为 1～65535；暂不支持 IPv6、用户认证字段、查询参数或 URL 片段。这是本程序当前校验器的范围，不是 RTMP 协议能力限制。

## 三、文件职责与调用关系

| 文件 | 当前实现 |
| --- | --- |
| `include/config.h` | 完整配置结构、接口契约、成功失败语义 |
| `src/config.c` | 字段表、逐行读取、值转换、校验和配置摘要 |
| `include/log.h` | 日志等级和对外接口，printf 格式检查声明 |
| `src/log.c` | 时间格式化、等级过滤、互斥保护、stderr 输出 |
| `src/main.c` | 命令行解析、调用配置加载、设置日志等级并退出 |
| `configs/ipc.conf` | 当前可解析配置，标注初值和占位参数 |
| `scripts/run.sh` | 根据脚本路径定位程序和默认配置 |
| `Makefile` | 保留 SDK 编译配置，补充 pthread 及本机测试入口 |
| `tests/` | 配置边界、命令行、启动路径、并发日志及失败原子性测试 |

运行顺序为：解析命令行 → 读取候选配置 → 校验全部字段 → 交付配置 → 设置日志等级 → 输出摘要 → 退出。

`--check-config` 明确表示只检查配置。当前普通启动也止于配置阶段，并额外说明媒体链路尚未实现；它不会进入等待循环。

## 四、配置模块实现细节

### 4.1 文件语法

- 每个配置项使用 `key=value`，区分大小写。
- 支持空行和去掉前导空白后以 `#` 开头的整行注释。
- 自动去掉键和值两端的空白。
- 支持 LF、CRLF、文件开头的 UTF-8 BOM，以及没有末尾换行的文件。
- 不支持行内注释、引号语法和环境变量替换。
- 每行最多 1023 字节，不含 LF；过长行直接报错。
- 拒绝 NUL 和异常控制字符；值内部也不允许控制字符。

例如 `video.fps=30 # fps` 不会被默认为 30，而是报告数值格式错误。这样不会把错误后缀无声忽略。

### 4.2 统一字段表

`ConfigField` 记录配置键、字段类型、`IpcConfig` 中的偏移、字段大小、数值上下界和是否必填。解析器先查找字段，再按类型赋值；新增字段时同步修改结构体、字段表、配置示例和测试。

原先配置文件中的 `pixel_format`、`codec` 等字段也进入结构体并被明确校验，不再出现“配置中存在，但程序忽略”的情况。

除 `log.level` 默认为 `info` 外，其他键都要求显式出现。`output.rtmp_url` 键即使在禁用推流时也必须存在，但可以写成空值。

### 4.3 数值和固定值校验

数字转换先确认所有字符都是十进制数字，再使用 `strtoumax` 检查溢出，最后检查应用允许范围。拒绝负号、正号、小数和尾随字符；不能使用会把错误后缀吞掉的简单转换方式。

| 参数 | 初版允许范围或固定值 |
| --- | --- |
| 视频宽高 | 1280、720 |
| 视频格式与编码 | `NV12`、`h264` |
| 目标帧率 | 1～30 |
| 视频码率 | 64000～20000000bit/s |
| GOP | 1～300 帧 |
| 音频采样格式与编码 | `S16_LE`、`aac` |
| 音频采样率 | 7350、8000、11025、12000、16000、22050、24000、32000、44100、48000、64000、88200、96000Hz |
| 音频声道数 | 1～2 |
| 音频码率 | 16000～320000bit/s |
| 视频原始队列容量 | 1～16 个元素 |
| 音频原始队列容量 | 1～256 个元素 |
| 每路视频编码包队列容量 | 1～256 个元素 |
| 每路音频编码包队列容量 | 1～512 个元素 |

这些范围是初版软件策略，不代表声卡和 MPP 对所有组合都有硬件支持。音频采样率列表依据现有 AAC 编码器能力；最终还需与录音设备实际参数匹配。

视频设备要求 `/dev/` 下的非空绝对路径；音频设备要求非空，具体 ALSA 设备是否可打开由后续模块判断。录像路径要求绝对路径并以 `.mp4` 结尾，不在本阶段检查或创建父目录。

### 4.4 错误定位与事务式加载

加载函数内部使用局部 `candidate` 对象，并记录每个字段第一次出现的行号。只有全部解析、校验和输入文件关闭成功后，才赋值给调用者的 `IpcConfig`。

因此加载失败不会留下“部分新值、部分旧值”的配置。失败时返回负 errno 风格错误值，并输出文件、行号、键名和原因。缺失键没有对应行号，只报告文件和键名。

例如：

```text
[ERROR] [config] configs/ipc.conf:19: audio.channels: expected range [1, 2]
```

上面的行号仅示意，实际日志根据当前文件计算。

### 4.5 公共接口

| 接口 | 约定 |
| --- | --- |
| `ipc_config_load` | 读取并自动校验；0 成功，负值失败；失败时输出对象不变 |
| `ipc_config_validate` | 校验调用者已初始化的配置对象；不访问硬件或网络 |
| `ipc_config_dump` | 对已通过校验的配置输出 INFO 级别摘要 |

配置对象读取期间不能被其他线程并发修改。当前加载发生在业务线程创建之前。

## 五、日志模块实现细节

日志形式为：

```text
2026-09-18 10:00:00.123 [INFO] [config] video: device=/dev/video0 size=1280x720 ...
```

日志时间为系统本地日历时间，毫秒精度，仅用于阅读与排查；后续音视频时间戳仍需使用合适的单调时钟及采样计数。

| 等级 | 用途 |
| --- | --- |
| DEBUG | 配置来源等调试细节 |
| INFO | 配置摘要、阶段成功结果 |
| WARN | 推流处于禁用状态等可继续执行的情况 |
| ERROR | 参数错误、配置读取或校验失败 |

全局互斥锁保护最低等级以及整条格式化输出，避免多个线程把一条日志拆开交错写入。默认等级为 INFO，配置全部有效后才应用 `log.level`。例如设置为 `warn` 后，成功摘要不显示，应结合退出码判断。

当前统一写入 stderr，可以由 Shell 重定向保存。接口不在信号处理函数内调用，也不实现日志轮转。GCC/Clang 的 printf 格式检查用于发现参数类型与格式字符串不一致。

## 六、编译和运行

### 6.1 Ubuntu 交叉编译

在项目根目录执行：

```bash
sh scripts/build.sh
```

SDK 路径不同时：

```bash
SDK_ROOT=/实际路径/rk3568_linux_sdk sh scripts/build.sh
```

输出为 `bin/ipc_camera`。构建保持 AArch64 SDK 工具链和 sysroot，新增 `-pthread`。不升级 FFmpeg，不链接 Ubuntu 的 x86_64 媒体库。

### 6.2 部署到开发板

按原有 SSH 或文件传输方式部署以下文件，保持相对位置：

| Ubuntu 文件 | 板端示例路径 |
| --- | --- |
| `bin/ipc_camera` | `/root/rk3568-ipc-camera/bin/ipc_camera` |
| `scripts/run.sh` | `/root/rk3568-ipc-camera/scripts/run.sh` |
| `configs/ipc.conf` | `/root/rk3568-ipc-camera/configs/ipc.conf` |

不要把 `bin/host/` 的本机测试程序部署到板端。必要时为板端 `bin/ipc_camera` 添加可执行权限。

在开发板任何目录都可以执行：

```bash
sh /root/rk3568-ipc-camera/scripts/run.sh --check-config
```

如果继续采用之前“只把程序放在 `/root/`”的方式，需要同时上传配置，并显式指定路径，例如：

```bash
/root/ipc_camera --config /root/ipc.conf --check-config
```

默认直接运行可执行文件时，配置路径是相对于当前工作目录的 `configs/ipc.conf`；由启动脚本运行时，传入的是脚本推导出的绝对路径。需要覆盖配置时：

```bash
sh /root/rk3568-ipc-camera/scripts/run.sh --config /userdata/ipc.conf --check-config
```

重复提供 `--config` 时采用最后一个值，因此用户参数可以覆盖脚本默认路径。

### 6.3 本阶段预期输出与退出码

默认配置应打印 720P/H.264、音频开发初值、队列容量、录像路径，以及：

```text
rtmp: enabled=false url=rtmp://SRS_SERVER_IP/live/stream
RTMP is disabled; an empty or placeholder URL is permitted
configuration validation passed; hardware parameters were not probed
```

普通启动还会提示采集、队列、编码和输出未实现。`--check-config` 只检查后退出。

| 退出码 | 含义 |
| --- | --- |
| 0 | 配置检查完成，或帮助信息显示完成 |
| 1 | 配置加载或校验失败 |
| 2 | 启动参数错误 |

在执行命令后立即运行 `echo $?` 查看退出码。

## 七、当前边界

已实现的是配置驱动的启动检查和日志基础。队列、采集、编码、推流、录像、媒体同步和业务退出协调仍保留骨架。

下一阶段实现原始帧队列及关闭唤醒机制，再接入 V4L2 与 MPP H.264。届时才依据实际协商结果使用设备参数，并接入 SDK 的媒体头文件和目标库。
